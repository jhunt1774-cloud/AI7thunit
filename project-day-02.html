The ideas we need today

  • A dependency means something is needed first: A dependency arrow means one step needs information or an output from another.
  • Inputs, actions, and outputs: An input is information a part uses: tower height and position are inputs.
  • Abstraction keeps the relevant detail: Abstraction means leaving out details that do not help the current problem while preserving those that do.

The full explanations and code card are on today’s student lesson page.

The rules we will use and check

  • Names let us change the intended part: A stable name such as Tower_body identifies one object across revisions.
  • Bridge span depends on the river: Span is the distance the bridge must cover.
  • Decomposition supports implementation: Decomposition divides a large problem into parts that can be designed, built, and checked.

Try one with your teacher

1. For a home module, is roof color an input, an output, or always a dependency? Explain.

Show the worked answer after trying

It can be an input if the procedure uses it to choose the material. A created colored roof is an output. Color is not automatically something that must be built first; explain its role rather than memorize one category.

2. Which two details would you retain in a simplified map used to plan route width?

Show the worked answer after trying

House footprint width and location are strong choices. Keep river bounds and gate opening too when relevant. Individual shingles or decorative wall patterns can wait.
