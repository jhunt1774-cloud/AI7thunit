Learn this before doing today’s work

How to use this section: read the six explanations,follow the worked examples,then try the two guided questions. Your teacher will discuss them before assigning independent work. Return to the numbered explanation if you need help with a check question.

1. A dependency means something is needed first

A dependency arrow means one step needs information or an output from another. A roof needs the body’s top height before its own vertical position can be set. An arrow can be labeled “body supplies top height to roof.” It does not mean the roof is prettier or simply nearby. Any order that respects all required inputs can be valid.

2. Inputs, actions, and outputs

An input is information a part uses: tower height and position are inputs. Actions do the work, such as placing a body and roof. Outputs are the resulting named objects or reported values. A module contract records its job, inputs, outputs, dependencies, and tests. This tells another designer enough to build and check the part.

3. Abstraction keeps the relevant detail

Abstraction means leaving out details that do not help the current problem while preserving those that do. To plan a walking route, a house’s footprint, location, and height clearance can matter; tiny roof shingles usually do not. A rectangle is a useful stand-in for the footprint. Omitting its width would remove relevant information, not improve the abstraction.

4. Names let us change the intended part

A stable name such as Tower_body identifies one object across revisions. “Change Tower_body height to 8” is more precise than “change that thing.” Before creating a named object, check whether it already exists; updating it avoids accidental duplicates. Names are identifiers, not proof that the named object has the right values.

5. Bridge span depends on the river

Span is the distance the bridge must cover. If the river boundaries are x=-1 and x=1, the water width is 1-(-1)=2 units. We must know those boundaries before checking a bridge crossing. In our class world the river boundaries will be -2 and 2. A bridge may extend beyond both banks; knowing just its center cannot prove it spans the water.

6. Decomposition supports implementation

Decomposition divides a large problem into parts that can be designed, built, and checked. Listing “tower, bridge, home” is a start. Giving each part inputs, responsibilities, outputs, and tests makes the plan usable by a program. Submodules can divide a tower into body and roof. A shared interface states the information one part supplies to another, such as body_top.

Guided practice 1

For a home module, is roof color an input, an output, or always a dependency? Explain.

Compare your answer and reasoning

It can be an input if the procedure uses it to choose the material. A created colored roof is an output. Color is not automatically something that must be built first; explain its role rather than memorize one category.

Guided practice 2

Which two details would you retain in a simplified map used to plan route width?

Compare your answer and reasoning

House footprint width and location are strong choices. Keep river bounds and gate opening too when relevant. Individual shingles or decorative wall patterns can wait.

Connect the idea to our class world

A large problem becomes easier to manage when we decompose it into smaller parts. Lantern Reach contains a tower module, a bridge module, a home module, a grove module, and a gate module. Each module has inputs, work, and outputs. A tower may take a position and height as inputs and produce a body and roof as outputs. Decorative wishes become useful when they are attached to a specific module and a test.

Some modules depend on others. The terrain must have a known surface before a tower’s ground contact can be checked. The river corridor must be known before the bridge can be tested. A dependency arrow means “must be ready before,” not simply “looks near.” Independent tasks can be planned at the same time even though only the teacher executes Blender changes.

Abstraction means keeping the details needed for the current decision. A top-down rectangle can stand for a house when we are planning routes; roof shingles do not help that decision. Later, a roof shape may matter. We will preserve stable object names so that a later instruction changes a known module instead of accidentally replacing the whole world. Breaking a world into nouns is only a start. To support a program, each part also needs responsibilities, inputs, and tests.
