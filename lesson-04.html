Learn this before doing today’s work

How to use this section: read the six explanations,follow the worked examples,then try the two guided questions. Your teacher will discuss them before assigning independent work. Return to the numbered explanation if you need help with a check question.

1. A span is end minus start

Distance on a number line is right endpoint minus left endpoint. A span from -3 to3 is 3-(-3)=6 units, not zero. Adjacent planks meet when one right edge equals the next left edge. For 1-unit planks, each edge lies half a unit from its center. Count distinct positions as well as objects.

2. Efficiency needs a named measure

Efficiency means using fewer resources for the same required result. Name what you are comparing: written lines, edits, tool calls, object count, or elapsed time. A loop can reduce repeated writing and centralize edits. It does not by itself prove fewer created objects or faster rendering. Real timing needs actual measured trials.

3. A sequence and its trace

An algorithm is an ordered method. A trace table records values at each step. Starting x=-2 and adding 1 produces -2,-1,0,1 and so on. List every iteration so a copied duplicate or a skipped value is visible. The trace predicts positions before a live build and supports a later comparison with actual object data.

4. A loop changes representation

A loop repeats its body, the instruction inside it. Writing CREATE eight times and repeating one CREATE eight times can produce the same eight objects. The repeated version has a shorter written representation. Always count both loop iterations and resulting creations; they describe behavior, not the number of source lines.

5. Duplicate positions can hide a gap

Eight list entries need not be eight unique locations. If the last location repeats an earlier one, two planks may overlap and another interval remains empty. A count test alone misses that error. Check the complete sequence, uniqueness, adjoining edges, and endpoints to establish full coverage.

6. Keep an odd or even row centered

For n touching 1-unit planks centered around x=0, the first center is -(n-1)/2. Then add1 for each following center. Work parentheses first, division second, then the minus sign. For n=4, start=-(4-1)/2=-1.5. The centers -1.5,-.5,.5,1.5 span -2 to2.

Connect the idea to our class world

An algorithm is an ordered method for completing a task. Two algorithms may both produce eight bridge planks but use different representations. Algorithm A writes eight separate create instructions. Algorithm B repeats one instruction eight times while changing x. Repetition can make a procedure easier to revise. It does not automatically mean Blender will create fewer objects or render faster.

Our river corridor runs north–south from x=-2 to x=2. The bridge crosses east–west at y=-4. Eight touching planks are centered at x=-3.5,-2.5,-1.5,-0.5,0.5,1.5,2.5,3.5. Each plank is 1 unit long in x, 3 units wide in y, and 0.4 units high, centered at z=0.2. The bridge extends from x=-4 to x=4, leaving 2 units of bank coverage on each side of the river.

Before calling one algorithm efficient, name your measure. Source lines, human edits, tool calls, object count, and elapsed seconds are different measures. We will count explicit instruction lines and the edits needed when a request changes from eight to ten planks. We will not invent timing data. An off-by-one error happens when a process repeats once too often or too few times. A trace table lets us inspect every position before using a tool.
