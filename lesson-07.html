Learn this before doing today’s work

How to use this section: read the six explanations,follow the worked examples,then try the two guided questions. Your teacher will discuss them before assigning independent work. Return to the numbered explanation if you need help with a check question.

1. A bug report starts with a mismatch

A bug is behavior that does not meet the intended rule. Begin a report with expected behavior and actual behavior,including the evidence source. Then give reproduction steps,a possible cause,a minimal fix,and a retest. “It is broken” does not tell another person what happened or how to check the repair.

2. Calculate the clear gate opening

Clear opening is empty space between inner edges,not distance between post centers. Left inner edge=left center+left width/2. Right inner edge=right center-right width/2. Gap=right inner-left inner. Two posts can have separated centers yet touch or overlap if their widths fill that space. Calculate before judging the picture.

3. Regression tests protect earlier successes

After repairing one part,check that previously correct features remain correct. That is a regression test. A gate repair can have a local gap test plus a tower-height and bridge-count regression. Adding a new decoration is not itself a regression check;the check compares an earlier requirement with evidence after the change.

4. Change one relevant factor to investigate a cause

A hypothesis is a proposed explanation to test. If you change width,color,position,and height together,you cannot tell which change corrected the gap. To investigate width,keep other relevant values constant,change width,and recalculate/retest. A later repair may need multiple coordinated edits,but record each reason so the evidence remains understandable.

5. Minimum values and boundary tests

A minimum2-unit opening means gap≥2. Exactly2 passes;1.99 fails;2.01 passes. Test just below,at,and above a boundary to check the rule. Do not round1.99 to2 and silently pass it. Report enough decimal precision to preserve the decision. A missing post is a different invalid configuration,not a successful giant opening.

6. Visible opening is not the whole test

A hidden blocker can fill an opening even when the view appears clear. Inspect object names,bounds,and the space meant for passage. Vertical clearance matters too:the lintel bottom must leave the required height. A screenshot can support appearance,but hidden geometry and precise dimensions need additional evidence.

Connect the idea to our class world

Debugging is a systematic search for a cause. Start with expected behavior, record actual behavior, form a hypothesis, change one relevant thing, and retest. If you change color, location, dimensions, and code all at once, a successful result may not tell you which change fixed the problem.

The Lantern Reach gate uses two posts and a lintel, so travelers can pass through an opening rather than a solid box. The posts stand at (4,0) and (8,0), each 1 unit wide, 1 unit deep, and 4 units tall, centered at z=2. Their inner x edges are 4.5 and 7.5, giving a clear opening of 3 units. The lintel spans 5 units in x at center (6,0,4.5), height1, so its bottom meets the post tops at z=4.

A screenshot might make the gate look open while a hidden block still fills the gap. Tests therefore include object data and a check for an unwanted blocker. A regression test checks that a previously correct feature stays correct after a change. When fixing the gate, confirm the tower is still height8 and the bridge still has eight planks. A failure report should describe a reproducible case, not blame a person or say merely “it is broken.”

Support desk role play

Partner A receives your bug report and must reproduce it only from your words. Partner B records missing information without guessing. Swap roles. Individually rewrite a report with exact names, dimensions, coordinates, and reproduction steps; attach a before/after trace and one regression check.

Turn in: Two report drafts, missing-information notes, before/after trace.

Further challenge

Boundary policy

Specify valid gate openings with inclusive inequalities. Create boundary tests just below, at, and above the minimum, and explain how measurement rounding could hide a failure. Propose a reporting precision.

Turn in: Your supported explanation,trace,or revised plan.

If technology fails

Use the faulty numeric report and draw cross-sections. Students physically test a 2-unit paper traveler through scaled openings. Record simulated versus measured paper results separately; use the same bug-ticket process without Blender.
